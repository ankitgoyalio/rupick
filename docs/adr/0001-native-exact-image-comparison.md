# Native exact image comparison

For milestone 1 (#4), support Apple silicon Macs running macOS 15 and later using SwiftUI with AppKit file panels. Observation provides a per-window project session; discovery, decoding, comparison, and preview thumbnail generation run outside the main actor. Retain the App Sandbox with user-selected **read-only** file access and hold security-scoped access for the active window and worker lifetime. Debug builds use local ad-hoc signing; distribution signing and notarization remain release work. For #9, read-only security-scoped bookmarks persist the ten most recent project folders. The workspace validates resolved folders and renews bookmarks on reopening. Window identity uses canonical folder locations, while sessions retain the granted URL for file access. Comparisons and review state remain per window. ADR 0002 extends the original session-only decision with validated local restoration of reviews in windows left open when quitting.

Exact matching compares equal dimensions and every decoded component after ImageIO decoding, EXIF orientation, and Core Image conversion to extended sRGB using unpremultiplied 32-bit floating-point RGBA. Clear RGB only when alpha is exactly zero. This avoids the low-alpha quantization of an 8-bit premultiplied bitmap, retains 16-bit image distinctions and wide-gamut colour, and gives an explicit common colour space. Dimensions narrow candidates before pixel rendering. SHA-256 fingerprints narrow comparisons without retaining decoded pixels for an entire incoming batch; fingerprint matches are verified with full component equality. There is no tolerance, resizing, cropping, or padding adjustment. Non-orientation metadata does not participate; colour profiles intentionally do because they determine displayed colour. JPEG files qualify only when normalized decoded pixels agree. The first frame is used for animated PNGs. Unsupported representations and images above 16,777,216 pixels or 8,192 pixels on either axis are reported as skipped/unreadable rather than classified as non-matches.

Discovery stays within the selected root: do not descend through symbolic links, and reject catalog metadata and representation paths resolving outside that root. Identity is the catalog entry's full location, never its display name alone. Changes to normalization can change exact-match decisions, so update behavioral fixtures and revisit this decision before changing the comparison policy.
